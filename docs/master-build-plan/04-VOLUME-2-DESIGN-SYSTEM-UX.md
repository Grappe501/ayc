# Arkansas Youth Coalition (AYC)
# Volume II
# Design System & User Experience Standards
## Version 1.0

**Status:** Canonical Volume 2 — constitution for the entire user experience.  
Every screen, button, dashboard, form, animation, icon, table, and future application under the AYC ecosystem shall conform to this standard.

---

## Purpose

This document establishes the complete visual language, interaction standards, and user experience principles for the Arkansas Youth Coalition Workbench.

It exists to ensure that AYC feels like one unified product regardless of how many features are added over time.

---

## Design Philosophy

The Workbench should feel like a platform built for the next generation of leaders.

- Not a government website.
- Not a corporate CRM.
- Not social media.

Instead, it should communicate energy, optimism, professionalism, trust, and purpose.

Every page should answer one question for the user:

> "What should I do next?"

Confusion is considered a design failure.

---

## Experience Doctrine

The experience itself is part of leadership development.

The platform should:

- Reduce anxiety.
- Encourage participation.
- Reward progress.
- Celebrate leadership.
- Remove unnecessary complexity.
- Guide users naturally from one meaningful action to the next.

---

## Design Pillars

### Clarity

Everything important should be immediately visible.  
Users should never have to guess where something is located.

### Focus

Every page should have one primary purpose.  
Avoid competing calls to action.

### Confidence

Users should always understand:

- Where they are.
- What they can do.
- What happens next.

### Momentum

Every completed action should naturally lead into another meaningful action.  
Leadership is a journey rather than a collection of isolated tasks.

### Humanity

Technology should feel warm.  
Friendly language. Positive encouragement. Minimal technical terminology.

---

## Visual Identity

The Workbench should communicate:

Modern · Youthful · Hopeful · Professional · Organized · Accessible · Optimistic · Arkansas-rooted · Mission-driven

---

## Brand Personality

If the platform were a person it would be:

- Confident without arrogance.
- Intelligent without complexity.
- Welcoming without being childish.
- Professional without being corporate.
- Ambitious without being overwhelming.

---

## Color Philosophy

Colors communicate emotion before words.

The system should emphasize:

- Deep backgrounds
- Bright highlights
- Warm surfaces
- Strong contrast
- Accessible readability

### Primary Palette

| Token | Role |
|-------|------|
| **Midnight Blue** | Primary application background. Trust, stability, leadership. |
| **Electric Blue** | Primary action color. Buttons, links, highlights, progress indicators. |
| **Arkansas Red** | Used sparingly. Alerts, important CTAs, special announcements. Never dominate. |
| **White** | Content surfaces. Cards, panels, forms. |
| **Light Gray** | Secondary surfaces, borders, section backgrounds. |
| **Success Green** | Confirmation messages, achievements, completed tasks. |
| **Amber** | Warnings, pending actions, items needing attention. |

Exact hex values will be locked when brand tokens are finalized; names and roles above are binding.

---

## Typography

Typography creates hierarchy.

- Use large headings.
- Generous spacing.
- Readable paragraph widths.
- Avoid walls of text.

### Heading Scale

1. Hero  
2. Page  
3. Section  
4. Card  
5. Body  
6. Caption  
7. Micro  

Each level should clearly communicate importance.

---

## Spacing Philosophy

Whitespace is intentional.  
Never fill every available pixel.  
Breathing room increases comprehension.  
Every screen should feel open.

---

## Layout System

Every page follows the same hierarchy:

```
Navigation
    ↓
Hero
    ↓
Primary Content
    ↓
Supporting Content
    ↓
Next Action
    ↓
Footer
```

Consistency reduces cognitive load.

---

## Navigation

Navigation should always remain simple.

**Maximum primary items (long-term shell):**

- Dashboard
- Directory
- Teams
- Events
- Resources
- Profile

Never exceed **seven** primary navigation items.

**Phase 1 subset** (from Phase 1 system design): Vision · Teams · Directory · Leader Entry — expand toward the full shell only as boards ship.

---

## Cards

Cards are the primary interface element for workbench boards and directories.

Each card contains:

- Title
- Description
- Optional statistic
- Primary action
- Secondary action (optional)

Cards should encourage exploration.

Landing/hero composition follows Phase 1 system design (strong brand-first hero; avoid card clutter in the first viewport).

---

## Buttons

### Button hierarchy

| Type | Treatment |
|------|-----------|
| **Primary** | Large filled. Only one per section. |
| **Secondary** | Outlined. Less visual weight. |
| **Tertiary** | Text only. For navigation. |
| **Danger** | Reserved for destructive actions. |

---

## Forms

Every form should:

- Explain why information is requested.
- Require only necessary fields.
- Provide immediate validation.
- Never lose user input unexpectedly.
- Display confirmation after submission.

---

## Tables

Tables should never overwhelm.

Support:

- Search
- Filtering
- Sorting
- Responsive mobile layout
- Expandable details

---

## Icons

Icons support understanding.  
Never replace labels.  
Icons are helpers—not navigation.

---

## Photography

Photography should feature:

- Real students.
- Real communities.
- Real Arkansas locations.
- Authentic interactions.

Avoid obvious stock photography whenever possible.

---

## Illustrations

Illustrations should be:

- Simple
- Modern
- Inclusive
- Optimistic

Used sparingly.

---

## Motion Design

Motion exists to explain. Never distract.

**Acceptable motion:** Fade · Slide · Expand · Progress · Celebration  

**Maximum animation duration:** 300 milliseconds.

---

## Loading States

Never show blank screens.

Use:

- Skeleton cards
- Progress indicators
- Friendly loading messages

---

## Empty States

Empty screens should encourage action.

Example:

> No leaders have been added yet.  
> Let's build the first team.

Every empty page should include a clear next step.

---

## Success Messages

Celebrate accomplishments.

Examples: Leader Added · Contact Saved · Directory Updated · Feedback Submitted  

The interface should reward participation.

---

## Error Messages

Never blame the user.

Explain:

1. What happened.
2. Why.
3. How to fix it.

Keep language positive.

---

## Mobile First

The phone experience is the primary experience.

Every feature must function comfortably using one hand.

- Large touch targets
- Readable typography
- Minimal scrolling

---

## Tablet Experience

The tablet becomes the ideal leadership dashboard.

- Split views
- Multi-column layouts
- Persistent navigation

---

## Desktop Experience

Desktop emphasizes productivity.

- Larger dashboards
- Multiple panels
- Advanced tables
- Analytics

---

## Accessibility

The platform should exceed minimum accessibility standards whenever practical.

Support:

- Keyboard navigation
- Screen readers
- High contrast
- Readable fonts
- Color-independent communication
- Reduced motion

---

## Dashboard Philosophy

Every dashboard answers four questions:

1. Where am I?
2. What needs attention?
3. What should I do next?
4. How am I making progress?

Nothing else is more important.

---

## Gamification Philosophy

Leadership should feel rewarding.

Celebrate: new leaders · completed events · volunteer growth · training · milestones  

Recognition should encourage service rather than competition.

---

## Feedback Philosophy

The Workbench will never be considered "finished."

Every page should encourage feedback.

Leadership builds the platform.  
The platform builds leadership.

---

## Future Design Evolution

Future enhancements may include:

- Dark Mode
- Personal themes
- Interactive maps
- Achievement systems
- Animated dashboards
- AI assistants
- Personalized home screens
- Advanced visual analytics

These additions should enhance—not replace—the core principles established in this document.

---

## Design Commandments

1. Simplicity over complexity.
2. Consistency over creativity.
3. Clarity over decoration.
4. Function before features.
5. Experience before technology.
6. Mobile before desktop.
7. Accessibility before aesthetics.
8. People before software.
9. Leadership before administration.
10. Every screen should inspire action.

---

## Closing Principle

The Arkansas Youth Coalition Workbench is more than software.

It is a digital home for a generation of leaders.

Every design decision should strengthen that purpose.

## Architectural note (library structure)

Three parallel constitutions should follow this volume:

| Volume | Focus |
|--------|--------|
| **3 – Technical Architecture** | Repositories, Netlify, database, APIs, deployment, coding standards |
| **4 – Data Architecture** | Tables, fields, relationships, IDs, code systems, naming, audit logging, expansion |
| **5 – Product Architecture** | Boards, dashboards, workflows, permissions, long-term feature roadmap |

This keeps the design system focused purely on user experience while allowing technical and product architecture to evolve independently.
